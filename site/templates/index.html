Why Chronix

Analytics in the engine

Forecasting (SES, Holt, Holt-Winters, ARIMA/SARIMA) and anomaly detection (Z-score, MAD, IQR, CUSUM, forecast-residual) run against zero-copy Arrow buffers, callable as FORECAST() and ANOMALY() from SQL. No Python sidecar, no data leaving the process.

Analytics guide →

Compression that fits the data

Most metric values started life as decimals — a meter reporting 231.45 W. ALP recovers the integer instead of XOR-ing bit patterns, which is worth 4–9× where the XOR codecs manage 1.0–1.2×, and decodes 3.3× faster than Chimp.

How encoding works →

Built for small machines

Chronix::open_small() is a ~48 MB preset with a flash-friendly WAL fsync policy, for eMMC and SD-backed gateways. The primary target is a 64-bit ARM box with 512 MB of RAM and days of offline operation.

Tuning guide →

Wire-compatible

InfluxDB line protocol, Prometheus remote write/read and PromQL, OTLP metrics, Arrow Flight SQL. Drop it in behind Telegraf, Prometheus, Grafana or the OpenTelemetry Collector without changing what they send.

API reference →

Security that stays out of the way

Cedar policy authorization, AES-256-GCM at rest, mTLS, Argon2 API keys, JWT/OIDC and a tamper-evident HMAC-chained audit log — all feature-gated, and an embedded build compiles none of it.

Security guide →

Open about what it isn't

Pre-1.0, single-node, and no production deployments yet. The distributed tier is frozen on purpose. Everything measured names the test that pins it, and the gaps are written down rather than implied away.
